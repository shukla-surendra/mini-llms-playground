## In Plain English

A large, capable model already "knows" a lot — not just the right answer to a question,
but *how confident* it is, and which wrong answers are "almost right" versus "way off."
Knowledge distillation is the technique of training a smaller model to imitate a larger
one's outputs, instead of (or in addition to) training it on raw human-labeled data. The
smaller model — the **student** — learns from the larger model's — the **teacher's** —
behavior, and often ends up meaningfully better than a same-sized model trained from
scratch on the same amount of raw data, because the teacher's outputs carry more signal
per example than a single correct-answer label does.

## The First-Principles Explanation

### Two genuinely different things both get called "distillation"

```
1. SOFT-LABEL (RESPONSE-BASED) DISTILLATION — the classical, white-box version
   Requires: access to the teacher's raw output PROBABILITIES (logits), not just
   its single predicted answer.
   Mechanism: train the student so its output probability distribution matches the
   teacher's output probability distribution, not just the one "correct" label.

2. SEQUENCE-LEVEL (BLACK-BOX) DISTILLATION — the practical version for most LLMs
   Requires: only the teacher's generated TEXT — no logits, no internals.
   Mechanism: treat the teacher's generated response as if it were a normal training
   label, and train the student with ordinary next-token cross-entropy
   (Chapter 3) on it — mechanically IDENTICAL to instruction tuning
   (Chapter 18), except the (prompt, response) pairs were generated by a
   stronger model instead of collected from humans.
```

This split matters practically: almost every "distill a popular hosted model" project
(the kind [Chapter 33](33_distilling_production_models_into_a_local_model.md) covers) is
forced into category 2, because commercial API providers return generated text, not raw
logits. Category 1 is what's used when you control both models directly (e.g.
DistilBERT-style compression of an open-weight model you have full access to).

### Soft-label distillation, precisely

For a classification-shaped problem (next-token prediction counts — the "class" is the
next vocabulary token, exactly as in [Chapter 3](03_how_neural_networks_learn.md)):

```
Standard training (Chapter 3):
    loss = cross_entropy(student_logits, one_correct_token)
    → the label is a single "hard" 0/1 target: 100% probability on the correct
      token, 0% on every other one of the 50,257 vocabulary entries.

Soft-label distillation:
    loss = KL_divergence(softmax(student_logits / T), softmax(teacher_logits / T))
    → the "label" is the TEACHER's full probability distribution over all 50,257
      tokens — not just which one it picked, but how confident it was, and how it
      ranked every other plausible token.
```

`T` (**temperature**) softens both distributions before comparing them. At `T=1` you get
the model's normal output probabilities, which for a well-trained model are usually
extremely peaked (one token near 100%, everything else near 0%) — that peakedness hides
almost all of the useful relative information between the wrong answers. Raising `T`
(e.g. to 2-4) flattens both distributions, which is what makes the teacher's *ranking* of
wrong answers ("almost right" vs. "way off") visible to the loss function at all. This
softened, cross-token relative information is what Geoffrey Hinton's original 2015
distillation paper called **"dark knowledge"** — signal a one-hot hard label structurally
cannot carry, because a hard label is only ever "1 correct answer, everything else
equally 0."

In practice, soft-label distillation combines both losses, not just the soft one:

```
total_loss = α × cross_entropy(student_logits, true_label)              # Chapter 3's loss
           + (1 - α) × T² × KL_divergence(soft_student, soft_teacher)   # the new term
```

(The `T²` factor corrects for the gradient-scaling effect of dividing logits by `T` before
the softmax — a standard detail from the original formulation, not something to derive
from scratch.)

### Feature-based and relation-based distillation, briefly

Two further categories exist, both requiring **white-box access and matched or bridgeable
architecture** between teacher and student:

- **Feature-based**: match intermediate hidden-layer activations, not just final output —
  the student is pushed to represent information *internally* the way the teacher does,
  layer by layer, not only to agree on the final answer.
- **Relation-based**: match the *relationships between* multiple examples' representations
  (e.g., which pairs of inputs the teacher considers similar), rather than any single
  example's output or activations directly.

Both are far less common for large language models specifically than for
smaller/vision-adjacent architectures, precisely because they need internal access that
today's most capable LLMs (accessed via API) simply don't expose. They're mentioned here
for the full landscape, not because this curriculum's own projects use them.

## Grounded in This Repo's Code

`custom-gpt-10m` and `custom-gpt-153m`'s entire training objective is one line —
[`src/gpt/data/dataset.py`](../../from_scratch/custom-gpt-10m/src/gpt/data/dataset.py):

```python
def next_token_loss(logits, targets, vocab_size):
    return F.cross_entropy(logits.reshape(-1, vocab_size), targets.reshape(-1))
```

This is exactly category-2 sequence-level distillation's loss function, unmodified — it's
the same `cross_entropy` call [Chapter 3](03_how_neural_networks_learn.md) already covers,
applied to whatever `targets` tensor it's handed. Nothing about this function cares
whether `targets` came from a human-written dataset (the current `data/sources.py`
registry) or from a stronger model's generated text — that's a difference in **where the
training data comes from**, not in the training mechanism, which is the core insight
[Chapter 33](33_distilling_production_models_into_a_local_model.md) builds the practical
pipeline around.

Soft-label distillation (category 1) would need a real code change here — `next_token_loss`
would need a second argument (`teacher_logits`) and a KL-divergence term, illustratively:

```python
import torch.nn.functional as F

def distillation_loss(student_logits, teacher_logits, targets, vocab_size, alpha=0.5, T=2.0):
    hard_loss = F.cross_entropy(student_logits.reshape(-1, vocab_size), targets.reshape(-1))
    soft_loss = F.kl_div(
        F.log_softmax(student_logits / T, dim=-1),
        F.softmax(teacher_logits / T, dim=-1),
        reduction="batchmean",
    ) * (T ** 2)
    return alpha * hard_loss + (1 - alpha) * soft_loss
```

This would only be usable with a **teacher this repo has direct logit access to** — e.g.
running one of the `local_llms/` or `base_models/` checkpoints locally as the teacher and
capturing its logits during data generation. It is not usable against a commercial API
teacher (see [Chapter 33](33_distilling_production_models_into_a_local_model.md)), which
is exactly why that chapter's practical recipe uses category 2, not this function.

## Deep-Dive: Why Distillation Actually Works

The intuitive objection is reasonable: "if the student just imitates the teacher's
outputs, how can it end up better than training on the same raw data directly?" Two real
mechanisms answer this:

1. **Dark knowledge is genuinely extra signal, not noise.** A hard label answers one
   question ("what's correct?"). A teacher's soft distribution answers a *much* richer
   one: "how correct, and how does every plausible alternative rank?" For next-token
   prediction specifically, a teacher's distribution over the next token routinely
   encodes real linguistic/semantic structure (e.g., synonyms clustering with similar
   probability mass) that a single correct-token label cannot represent at all. Training
   against that structure is training against strictly more information per example.
2. **A capable teacher effectively pre-filters and pre-organizes the learning problem.**
   For the sequence-level case specifically ([Chapter 33](33_distilling_production_models_into_a_local_model.md)'s
   practical approach): a strong teacher's *generated* responses are typically
   better-structured, more consistent in format, and less noisy than a raw scraped or
   crowd-sourced dataset — which is a large part of why synthetic, model-generated
   instruction datasets (this repo's own `UltraChat 200k` source, generated by two
   ChatGPT models conversing) work as well as they empirically do, independent of any
   soft-label mechanism at all.

The honest limit: distillation is fundamentally an **upper-bounded approximation** of the
teacher, not a way to exceed it. A student cannot reliably learn a capability the teacher
never demonstrates, and a much smaller student has less capacity to absorb everything the
teacher expresses even when it is demonstrated — "distilled" does not mean "as good as,"
it means "as close as this student's capacity and this recipe's data allow."

## Common Misconceptions

- **"Distillation always needs the teacher's logits."** Only true for soft-label
  distillation. Sequence-level distillation — the version almost everyone actually uses
  against commercial hosted models — needs nothing but the teacher's generated text, and
  is mechanically identical to ordinary SFT ([Chapter 18](18_instruction_tuning_and_sft.md)).
- **"Distillation and fine-tuning are different techniques."** For the sequence-level
  case, they are the *same* training mechanism (next-token cross-entropy on (prompt,
  response) pairs) — the only difference is whether the response text was written by a
  human or generated by a stronger model.
- **"A distilled student can end up better than its teacher at everything."** No — it's
  bounded by what the teacher demonstrates and by the student's own capacity to absorb it;
  distillation is a compression/transfer technique, not a way to manufacture capability
  that was never in the training signal.

## Key Terms

- **Teacher / student**: the larger, already-capable model whose behavior is imitated
  (teacher), and the smaller model being trained to imitate it (student).
- **Soft-label (response-based) distillation**: training the student to match the
  teacher's full output probability distribution, not just its top answer — requires
  logit access to the teacher.
- **Sequence-level (black-box) distillation**: training the student with ordinary
  cross-entropy on the teacher's generated text as if it were a normal label — needs only
  the teacher's text output.
- **Temperature (`T`)**: a softening factor applied to both distributions before computing
  the distillation loss, making relative probabilities across wrong answers visible.
- **Dark knowledge**: the relative-probability information across a full output
  distribution that a single hard label structurally cannot encode.
- **Feature-based / relation-based distillation**: matching internal activations or
  cross-example relationships rather than final outputs — requires white-box access to
  matched or bridgeable architectures.
